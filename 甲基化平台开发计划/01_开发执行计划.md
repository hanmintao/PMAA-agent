# 多糖甲基化分析平台开发执行计划

平台目标是把甲基化实验记录、PMAA 参考资料、EI 质谱和色谱证据，通过确定性化学规则、谱库检索和LLM辅助判定，转化为可复核的糖残基连接组成报告。首个可交付版本接受 EI 汇总表和仪器导出峰表，输出候选、证据、歧义及质量状态；随后接入原始 GC–MS 和经校准的定量。LLM参与候选复核、异常解释、证据冲突检查和补测建议，其输出经后端核验后交人工复核。完整糖链序列、α/β 构型、D/L 构型和三维结构作为后续联合分析的独立模块。

本计划按一个多糖分析负责人、一个算法/后端工程师、一个前端工程师及共享实验员/测试人员估算。加入LLM适配、证据检索、输出校验和对照评测后，按14–16周准备经过限定范围验证的研究用平台；这是排期估算，标准品和仪器验证进度决定正式放行时间。使用远程LLM API时第一版不要求GPU；本地模型部署另作资源评估。

本文件为整合版主计划。第1–12节给出研发实施安排；第13节给出LLM接口、提示词、证据链和验收；第14节直接纳入完整的实验与判读规范，包括前处理、甲基化、水解、还原、乙酰化、GC/EI、连接映射和歧义处理；第15节逐项对应需求。阅读本文件即可获得完整搭建方案，配套文件作为独立查阅和机器可读附件。

配套文件：

- [实验与判读技术规范](02_实验与判读技术规范.md)：来源甄别、实验起始 SOP、GC 条件、连接映射、EI 规则、歧义和定量。
- [数据契约与验收用例](03_数据契约与验收用例.json)：可供研发直接转为数据模型、接口校验和自动化测试的结构化规格。
- [LLM接口契约与验收用例](04_LLM接口契约与验收用例.json)：请求/响应JSON Schema、示例、输出规则和LLM专项用例。

当前交付状态（2026-09-12 更新）：四份设计/接口规格已制定，`pmaa_platform` 已形成可运行的 V0.1+ / V0.2 研究原型，并导入 57 条定性 EI 参考记录；原始 GC–MS、完整数值谱库、报告 PDF/XLSX、权限/备份、真实 LLM 对照和湿实验方法转移仍未完成。文献已报道、代码测试通过与平台实测验证通过是不同状态；详细差异见 `pmaa_platform/docs/05_与四份设计文件差异审计.md`。

## 1. 版本范围与完成定义

| 版本 | 主要输入 | 主要输出 | 完成条件 |
|---|---|---|---|
| V0.1 资料与规则工作台 | XLSX/CSV/JSON 的参考 EI 表、实验方法、单糖组成 | 经审核的参考条目、离子候选、连接映射集合、证据缺口；LLM模拟适配器 | 可追溯到源文件单元格；不把“+”伪造为强度；多对一映射用例全部通过 |
| V0.2 峰表与LLM辅助平台 | 已积分峰表、每峰数值 EI 谱、RT/RRT、实验 QC、已审核知识库 | 候选排序、谱图对照、LLM证据评议、人工复核、连接组成报告 | 同方法标准支持的衍生物可以确认；LLM引用/数值/规则通过校验；报告可重放 |
| V1.0 研究用正式版 | 已验证来源的 GC–MS 原始文件/开放格式、上述输入 | 峰提取、解卷积、保留校正、经校准定量、审核报告 | 限定化学范围及指定仪器方法完成盲测；原始数据、规则与报告版本闭合 |
| V1.1 专项扩展 | 糖醛酸氘标记、硫酸化/氨基糖/果糖等专项数据 | 专项残基与取代信息，未解决项 | 每类单独验证；不能继承中性醛糖模块的准确性结论 |

只提供 EI 离子汇总表时，V0.1 已可运行候选检索，但不具备峰提取、共洗脱分析或摩尔定量所需的数据。表格导入功能与原始数据分析功能必须分别验收。

首批支持范围：常见中性醛己糖、醛戊糖和 6-脱氧醛己糖；参考库必须明确 NaBD4/NaBH4 和环型适用范围。含糖醛酸、硫酸基、氨基糖、果糖、3,6-内醚糖及天然修饰的样品在建档时自动转入对应分支，尚未验证的分支允许保存和人工研究，不签发超出范围的自动结论。

## 2. 必须先固定的科学产品规则

1. 一条 PMAA 化学实体可对应多个原始残基。衍生物身份和原残基映射分别判定。
2. `2,3,6-Me3` 只有在适用的吡喃醛己糖框架下才映射为 4-连接；环型未知时同时保留可能的呋喃型来源。
3. α/β、D/L 不由常规非手性 GC–EI 甲基化分析生成。外部证据确认后可显示，但必须标出来源。
4. 数值 EI 谱与只有“+、红色强峰”的定性表使用不同评分器。
5. 未列出的离子不自动等于未检出；缺测、未报告和明确未检出为不同数据状态。
6. RT、RRT、RI 分开保存；保留证据绑定柱、完整程序和参照物。
7. 最高匹配分数不是确认结论，0.93 的相似度不是 93% 的正确概率。
8. 无校准时输出面积占比或明示半定量；不把峰面积或面积/分子量作为通用准确 mol%。
9. 未检出的单糖通常作为冲突提示；只有验证了灵敏度和回收能力的组成数据才可作强排除条件。
10. QC 失败后保留候选供研究，但冻结正式结构和定量放行。
11. LLM建议和算法原始判断分开保存；模型不得生成新的实测峰、保留值、校准值或实验条件执行记录。
12. 原残基不可辨识关系必须在模型建议和最终报告中保留；LLM输出符合JSON格式不等于科学结论正确。

这些规则进入后端规则引擎、界面文案和自动测试，不能只写在说明书里。科学依据和例子见技术规范。

## 3. 技术架构

```text
文件/峰表/方法记录
       ↓
导入与数据审计 → 原始文件存储（哈希、权限、来源）
       ↓
参考库审核 → PMAA 化学实体 ←→ 原残基候选
       ↓
方法兼容检查 → 信号质量检查 → EI/保留候选匹配
       ↓
歧义处理与单糖组成核查 → 校准定量 → 样本级 QC
       ↓
证据包＋经审核知识库 → LLM API辅助评议
       ↓
引用/数值/化学规则校验 → 接受建议或返回规则结果
       ↓
人工复核 → 固定版本报告 → 可重放归档
```

采用模块化单体 API 加后台计算进程，避免第一版拆成大量微服务。建议 Python 分析核心、FastAPI API、React/TypeScript 界面、PostgreSQL 元数据。大体积原始谱文件保存在受控文件存储/对象存储，不塞进数据库 JSON 字段；JSONB 用于方法快照和结构化证据。[FastAPI](https://fastapi.tiangolo.com/)；[PostgreSQL JSON 类型](https://www.postgresql.org/docs/current/datatype-json.html)

开发开始时锁定运行时与依赖版本，提交锁文件及环境清单；分析任务记录程序版本、参数哈希和随机种子（若使用随机算法）。本地研发和单实验室部署先采用单机容器环境；计算队列接口预留分布式扩展。

原始数据转换与分析服务隔离。优先读取经过验证的 mzML/netCDF；厂商目录必须先识别具体仪器及软件版本，不能承诺所有 `.D` 或 `.RAW` 都可读。ProteoWizard 的 msconvert 可作为转换选项，实际厂商格式支持、操作系统和授权条件在接入时核实，必要时设置 Windows 转换工作站。[msconvert 官方说明](https://proteowizard.sourceforge.io/tools/msconvert.html)

GC–MS 解卷积以离子色谱的共变和峰形为依据，AMDIS 可用作外部比较基线。是否嵌入其程序需独立核对分发条件；不把它默认视作可直接嵌入的开源库。[NIST AMDIS](https://chemdata.nist.gov/dokuwiki/doku.php?id=chemdata%3Aamdis)

## 4. 模块、接口及责任

| 模块 | 输入→输出 | 实现边界 | 主要负责人 |
|---|---|---|---|
| M01 样本与方法登记 | 样品属性、前处理、仪器条件→样本/方法版本 | 原始记录和修改历史保留；未知字段不自动补齐 | 分析负责人＋后端 |
| M02 表格导入 | 原表→字段映射预览、标准条目、隔离错误行 | 支持合并单元格、字体/填充色、单位；宏不执行 | 后端 |
| M03 参考库管理 | 文献/标准谱→审核后的版本化参考库 | 参考谱、化学实体、原残基、保留观测分表 | 后端＋分析负责人 |
| M04 化学映射引擎 | 骨架、环型、O-Me、标签→候选连接/乙酰位置 | 确定性规则；支持一对多；氨基糖独立规则 | 算法 |
| M05 EI 检索 | 定性离子或数值谱→候选与证据 | 两种模式独立；噪声/公共离子降权 | 算法 |
| M06 色谱证据 | RT/RRT/RI与方法→兼容性、偏差、共洗脱提醒 | 方法不匹配时不应用文献固定容差 | 算法＋实验员 |
| M07 原始数据处理 | 扫描序列→峰、组分谱、积分与残差 | 原始数据可回看；共洗脱不可辨识时不强拆 | 算法 |
| M08 定量与 QC | 校准、积分、空白/重复→含量、等级、质量门 | TIC/FID/离子积分分别校准；组合峰不重复计量 | 算法＋分析负责人 |
| M09 复核界面 | 候选与证据→有原因的审核决定 | 禁止以勾选“确认”绕过证据门槛 | 前端＋后端 |
| M10 报告与归档 | 冻结分析版本→HTML/PDF、XLSX/JSON | 未知峰、歧义、分母和方法必须随报告交付 | 前端＋后端 |
| M11 LLM网关 | 证据包＋模型配置→结构化辅助评议 | 服务商适配、超时/限流、密钥、成本与版本记录 | 后端 |
| M12 知识检索和证据包 | 已审核参考库＋候选→证据快照 | 化学字段过滤优先，文段检索补充；保留歧义类 | 算法＋科学 |
| M13 LLM结果校验与评测 | 模型输出→通过/拒收/需审核 | 检查引用、事实、规则、候选覆盖及不确定性；与无LLM基线比较 | 算法＋测试＋科学 |

## 5. 数据模型

| 实体 | 关键字段 | 关系/约束 |
|---|---|---|
| Sample | sample_id、来源、批次、干基量、组成、修饰、适用分支 | 不把 SEC 单峰当单一序列 |
| PreparationBatch | batch_id、独立制备编号、步骤实测值、试剂批次 | 甲基化后分装仍属同一独立制备 |
| MethodVersion | 柱相/规格、温程、载气模式、EI能量、扫描范围、标签路线 | 一旦用于已出报告分析即不可原位修改 |
| SourceRecord | DOI/URL、文件哈希、页/表/单元格、获取深度、许可状态 | 来源等级与本地验证状态分开 |
| Derivative | PMAA规范名、骨架、O-Me/O-Ac、氘标记原子位置、立体信息 | 不用“原残基名称”充当唯一主键 |
| ResidueMapping | derivative_id、原糖、环型、连接位点、适用前提 | 同一 derivative_id 允许多行 |
| ReferenceSpectrum | derivative_id、来源、数值谱/定性离子、能量、标签、覆盖范围 | 不把缺失强度填0或100 |
| RetentionObservation | derivative_id、method_id、RT/RRT/RI、参照物、重复误差 | 与谱图实体解耦，允许多柱多批次 |
| RawRun | 文件哈希、转换器版本、方法快照、校准/空白/样品角色 | 同一文件幂等导入，不覆盖原件 |
| Peak / Component | 起止RT、apex、积分、谱、纯度、解卷积版本 | 一个色谱峰可对应多个组件；也可保留未分辨组合 |
| CandidateEvidence | 参考条目、EI分数、保留证据、冲突、缺失项 | 分数不能代替证据等级 |
| Calibration | 检测器/积分方式、标准量、模型、适用范围、有效批次 | 超范围不输出校准 mol% |
| Decision / Review | 衍生物等级、映射等级、QC、审核人/原因 | 五种状态维度独立保存 |
| ReportSnapshot | 输入哈希、库/规则/方法版本、结论、审计轨迹 | 重跑生成新版本，不改历史 |
| LLMProviderConfig | provider、base_url、model、secret_ref、能力和限额 | 密钥仅后端读取，版本变更留痕；不把兼容接口当能力完全等价 |
| EvidenceBundle | bundle_id、分析版本、候选、事实、规则、来源、哈希 | 发给模型的内容冻结保存，包含被保留的并列来源 |
| LLMAssessment | 模型/提示词/Schema版本、原响应、解析结果、用量、错误 | 建议不直接覆盖Decision；拒收响应也保留审核原因 |
| LLMValidation | 引用存在性、数值一致性、硬规则检查、人工审核 | 引用存在仅是必要条件，不自动证明语义支持 |

五个状态维度：`qc_status`、`derivative_identity_level`、`residue_mapping_level`、`quantification_level`、`review_status`。例如：PMAA 已确认、原残基仍有两种环型候选、只能半定量，是一个合法而常见的结果。

## 6. API 草案

| 方法与路径 | 用途 | 必须返回/检查 |
|---|---|---|
| POST /v1/imports | 上传文件并生成审计任务 | 文件哈希、类型、job_id；文件大小/压缩包展开限制 |
| GET /v1/imports/{id}/preview | 表头、色彩含义和字段映射预览 | 每条源行、待确认字段、错误原因 |
| POST /v1/imports/{id}/commit | 提交审核通过的导入 | mapping_version、审核者；错误行不能静默丢弃 |
| POST /v1/samples | 建档 | 适用范围分支、缺失元数据 |
| POST /v1/methods | 新建方法版本 | 单位和必填项校验；版本号 |
| POST /v1/analyses | 创建分析任务 | 输入、方法、库、规则版本与幂等键 |
| GET /v1/jobs/{id} | 查询任务状态 | queued/running/succeeded/failed及具体原因 |
| GET /v1/analyses/{id}/components | 组分与候选 | 分项证据、歧义、建议补测，不只Top1 |
| POST /v1/analyses/{id}/reviews | 提交人工复核 | 选择、证据引用、原因、审核人；不能伪造缺失证据 |
| POST /v1/analyses/{id}/reports | 固定并导出版本 | QC失败仅可导出明确标识的草稿 |
| GET /v1/references/{id}/provenance | 查看来源链 | 源文件/页/单元格、审核和版本历史 |
| POST /v1/llm/providers | 配置服务商和模型 | 管理权限；写入密钥引用，返回脱敏信息 |
| POST /v1/llm/providers/{id}/test | 无样本连接和能力测试 | 结构化输出/拒绝/截断适配；不发送实验数据 |
| POST /v1/analyses/{id}/llm-assessments | 请求LLM辅助复核 | 分析版本、组分、配置版本；服务端构建证据包 |
| GET /v1/llm-assessments/{id} | 获取辅助评议和校验结果 | 原算法与模型建议并列、成本、错误、证据引用 |
| POST /v1/llm-assessments/{id}/reviews | 审核LLM建议 | 接受/部分接受/拒绝及理由；独立执行正式结果门槛 |

长任务异步执行，前端可显示各阶段进度。接口错误采用稳定代码，例如 `LABEL_UNKNOWN`、`RETENTION_METHOD_MISMATCH`、`COMPOSITION_CONFLICT`、`IDENTICAL_DERIVATIVE_ORIGIN`、`QUANT_CALIBRATION_MISSING`、`QC_FAILED`。

## 7. 十四至十六周任务安排

实验验证与软件开发同步进行。以下周数以人员和仪器可用为前提，不把采购、全文获取或补实验时间隐藏在软件工期中。

| 阶段 | 时间 | 交付物 | 放行条件 |
|---|---|---|---|
| P0 范围与证据冻结 | 第1周 | 样品范围、来源审计表、字段字典、标准清单、实验方法、LLM契约 | 科学负责人签认；不确定元数据明确列出 |
| P1 导入与化学规则 | 第2–3周 | EI导入、PMAA映射、候选工作台、LLM模拟网关 | 化学逻辑与导入用例通过；V0.1 |
| P2 数值谱与LLM接入 | 第4–6周 | 数值EI、保留检查、证据包、真实API适配、结构化响应校验 | 引用和硬规则检查通过；缺证据不能升级 |
| P3 复核、定量与归档 | 第7–9周 | 校准/QC、LLM建议复核、方法库、版本报告 | 无校准不输出准确mol%；模型失败可回退；V0.2 |
| P4 原始数据与共洗脱 | 第10–12周 | 一个仪器来源、mzML、积分、解卷积、组合峰 | 标准混合物与人工基线对比；不能分辨不强拆 |
| P5 盲测与研究用发布 | 第13–14周 | 有/无LLM对照、科学盲测、备份恢复、操作手册 | 第9节与第13节验收通过，发布限定范围V1.0 |
| P6 预留修正 | 第15–16周 | 近邻误判、方法差异、LLM越界与性能问题修正 | 只针对新改动/失败项重测，必要时缩窄放行范围 |

第1周即可开始：建立中性标准全流程、收集现有仪器方法及至少一个原始测试文件；软件端建立契约、导入预览和全部化学反例。即使 EI 汇总表还没到，也可完成这些任务。真实数据到达后替换测试夹具中的占位元数据，重新审计，不使用虚构样本演示准确率。

## 9. 实验与算法验收

### 9.1 实验数据准备

至少准备三类材料，不能只用文献中的几张谱图完成验证。

- 身份明确的 PMAA 标准或经独立结构确认、能产生目标 PMAA 的标准材料：建立 EI 与保留分布。
- 独立称样和完整衍生化的标准多糖：验证欠甲基化、水解损失及批次差异。单次甲基化后的四份分装不算四次全流程重复。
- 有意设置的困难样本：欠甲基化、混合/共洗脱、不同浓度、盐干扰、标签差异、库外组分、仅定性EI输入。

首批目标建议覆盖不少于20个经审核的衍生物实体、至少3类糖骨架及端基/2/3/4/6/支化连接；这是研发覆盖目标，不能强凑“20个已验证”。缺少实物或可靠谱图的实体保留候选功能，其确认功能不放行。

每个可确认实体建议至少3个独立制备批次，在不少于3天采集；关键近邻异构体用混标验证。初期样本量不足时只发布限定库的人工复核版。

### 9.2 建议的试运行指标

以下数值是本项目拟定的验收目标，需在首批实验后锁定，不是文献已验证性能或统一行业阈值。

| 项目 | 试运行目标 | 不满足时 |
|---|---|---|
| 数据解析 | 合法输入全部保留来源；异常输入明确报错；不丢行 | 阻止入库/提交 |
| 化学逻辑 | 配套关键反例全部通过 | 阻止发布 |
| 定量信噪 | 以S/N≥10作为初始可定量筛选，结合校准LOQ验证 | 仅定性或低于LOQ |
| 空白 | 目标峰低于样本信号5%且低于预设报告影响限 | 批次/峰警报，复测 |
| 定量主要组分重复性 | 独立全流程CV≤15%；近LOQ另设范围 | 排查实验，禁止用反复积分掩盖 |
| 定量回收 | 有已知量标准时初设80%–120%，另报前处理回收 | 超范围不得自动校准报告 |
| 保留窗口 | 同方法标准估计中心与离散度；近邻峰另验选择性 | 文献值只作候选提示 |
| 色谱分离 | Rs≥1.5作为近邻标准直接积分的初始目标 | 进入已验证解卷积或组合峰报告 |
| 确认准确性 | 独立盲测中“confirmed”错误率目标≤1%，同时报告覆盖率和置信区间 | 提高门槛或缩窄支持范围 |
| 不可辨识样本 | 预设同一PMAA多来源反例100%保留歧义 | 阻止发布 |
| 重放 | 确定性计算相同输入/版本得到相同结果；LLM建议回放已保存响应 | 修复后重验；重新请求模型属于新评议版本 |

若只有30次独立确认且零错误，也不足以证明错误率低于1%；零错误时95%上界约为3/n，达到约1%需约300个适当独立的确认实例，且仍不能外推到未覆盖糖种/方法。按“原始样品及独立制备批次”划分开发、阈值设定和盲测集，不把同一针扫描或同一衍生物分装泄漏到不同集合。

同时报告：衍生物识别准确性、候选集合覆盖率、自动确认覆盖率、歧义保留率、定量误差、未知组分拒识率。单一Top1准确率不足以评价平台。

## 13. LLM API辅助判定模块

### 13.1 功能和决策分工

LLM的主要价值是结合实验记录、谱库候选和文献规则解释复杂情况，并指出最值得补充的证据。采用“规则/谱库生成候选→检索已审核资料→LLM评议→程序校验→人工复核”的流程。第一版不训练专用大模型；先用自有验证集评估可接入模型，再决定是否需要微调。

| 场景 | LLM实际工作 | 进入正式结果前的条件 |
|---|---|---|
| EI表导入 | 建议复杂表头、缩写、注释和颜色含义的字段映射 | 解析器保留源单元格；不明确的映射由人确认 |
| 候选比较 | 逐项说明候选与EI、保留、组成、标签的相容性；建议复核顺序 | 引用必须来自本次证据包；并列歧义类不被删除 |
| 实验异常 | 结合溶解、甲基化重复、空白和水解记录提出可能原因 | 标为假设；每条给依据和验证建议，不写成已发生事实 |
| 共洗脱/异构体 | 判断证据更支持共洗脱、相似EI还是同一PMAA多来源 | 依据由规则和谱证据支持；不能声称恢复化学上已丢失的信息 |
| 补测建议 | 建议同柱标准、不同极性柱、重做衍生化或NMR环型证据 | 建议限定在已审核方法菜单；不能自动执行或修改实验SOP |
| 库缺项 | 提出扩展检索请求及糖种/框架线索 | 后端检索并重新计算；未检得可信条目时保留unknown |
| 结果说明 | 按已审核证据生成简洁判读说明 | 数字、单位、定量等级和不确定性与正式结果一致 |

LLM输出“建议支持/反对/证据不足”，不直接写数据库的confirmed或calibrated_molar字段。程序能验证的化学条件由程序验证；难以程序核验的自由文本诊断交分析负责人审核。模型提出有效的新冲突时，可将原本可确认的结果转入复核队列；不能凭模型分数提高证据等级。

### 13.2 可配置服务商接口

设置页面包含：配置名称、适配器类型、API Base URL、Model ID、后端密钥引用、连接测试、请求时间上限、输入/输出预算、并发数、单样本/每日费用上限，以及样本数据发送范围。用户选择启用API后，由后端代理调用；浏览器不保存或直连供应商密钥。

建议统一内部适配器：

```text
LLMProviderAdapter
  capabilities() -> 结构化输出、工具调用、可用生成参数
  assess(evidence_bundle, output_schema, generation_config)
    -> provider_response + parsed_assessment + usage + finish_status
```

提供OpenAI Responses适配器、经测试的Chat Completions兼容适配器和Mock适配器；有实际需求时再增加其他服务商原生适配器。兼容HTTP路径不代表支持相同JSON Schema、temperature、seed、推理预算或输出长度字段，必须逐项探测/适配。模型名称、可用权限和价格在部署时配置，不在科学规则里固定某一型号。

支持结构化输出的模型使用严格JSON Schema；普通JSON输出的模型也需后端独立验证，不支持所需结构时拒绝启用该适配模式。结构化输出能够约束格式，不能保证事实或化学推断正确；拒绝响应、截断和不完整响应需要独立处理。[OpenAI结构化输出说明](https://developers.openai.com/api/docs/guides/structured-outputs)

密钥保存在服务端Secret/环境配置，数据库仅存secret_ref；审计日志去除授权头。只发送当前分析所需的脱敏证据，不默认发送整份原始文件、客户身份或整个知识库。服务商的数据保留设置按实际账户和端点核对，例如store=false不能当作所有日志/缓存均零保留的保证。[OpenAI数据控制说明](https://developers.openai.com/api/docs/guides/your-data)

### 13.3 已审核知识库与检索

知识库分四层：本地标准实测、经核对的参考谱/方法、仅供候选的资料、禁用或隔离条目。每个知识片段记录source_id、原文位置、版本、证据级别和适用条件；记录“是否在本仪器方法验证”而不只记“来自论文”。

PMAA检索优先采用结构字段和实验方法过滤：骨架、甲基模式、N修饰、同位素标签、色谱方法兼容性。随后用EI检索产生候选；文段解释可用关键词/语义检索。禁止仅用文本向量相似度判断质谱相同，也不把语义检索相似度当实验置信度。

建议每个组分先选前5个不同PMAA实体作为初始上下文预算，再强制补齐每个实体的全部相容原残基映射及关键近邻冲突。若预算不足，应拆成小批或标记证据不足，不能截掉同一PMAA的另一个来源来制造唯一解。检索数量是可调工程参数，需用验证集检查候选召回率。

文献、表格注释和上传文件都作为数据处理；其中要求模型忽略规则、改变结果或调用外部地址的文字不作为指令。线上诊断默认只用已审核知识库；新增文献先进入审核区，再成为下一次分析的证据。

### 13.4 发送给LLM的证据包

一次请求绑定一个固定analysis_revision，可以包含一个或多个同样本组分。证据包由服务端构建，客户端不能自行宣称“QC已通过”或塞入未经验证的确认标签。

| 对象 | 发送内容 | 关键约束 |
|---|---|---|
| 样本上下文 | 脱敏ID、组成/检出能力、修饰、方法分支 | 不明项为unknown |
| 实验事实 | N1–N10实际记录、对照、甲基化重复、水解/还原标签、QC | 计划参数与实际测量区分 |
| 组分事实 | 峰编号、输入类型、数值谱或定性离子、RT、空白/饱和/峰纯度 | 离子“未测”与“未检出”区分 |
| 候选 | candidate_id、derivative_id、候选来源、原残基映射、分项分数 | 不仅传Top1；保留并列等价类 |
| 证据事实 | fact_id、字段、值、单位、来源位置、observed/derived/reference状态 | 模型引用ID，不能自行改数字 |
| 规则 | rule_id、适用前提、禁止推断、映射等价关系 | 只发送已审核版本 |
| 缺失项/冲突 | 标签未知、跨柱、无校准、环型歧义、弱峰等 | 模型必须保留关键缺口 |
| 已知定量 | 后端计算值、校准ID、分母和等级 | LLM不重新积分或推算响应系数 |

所有发送内容、哈希和库版本保存成EvidenceBundle。对大批次按组分打包复核，重复样本上下文可复用，但最终样本级一致性检查仍以全部组分为输入。

## 14. 实验与判读完整规范

本规范用于实现“实验数据→PMAA身份→糖残基连接候选→连接组成”的分析链。方法参数分为文献已报道的条件、平台拟定的试运行参数和本实验室验证后才能使用的放行阈值。任何给定文献的成功实例都不能替代新样品、新仪器和新色谱柱的方法转移验证。

### 14.1. 来源评估与前期资料修正

采用四级技术证据标记：E1为身份明确标准的本地原始数据、独立制备和校准；E2为已核对的原始论文方法/权威实验谱；E3为题录真实但仅摘要/片段可及或元数据不完整的资料；E4为专利、宣传或未独立验证的提议。等级用于本项目采纳，不是法定或通用行业分级。

| 来源 | 本次核验结果 | 可采纳内容 | 限制 |
|---|---|---|---|
| CCRC PMAA Spectral Database [1] | 官方页面及部分原始数值谱可核对 | PMAA结构、NaBD4标签、EI参考及残基映射 | 每个格子分别查实；有些只有示意图而无实测谱；不提供通用准确率 |
| Ďurindová等，1993 [2] | 期刊摘要确认专用PMAA谱库辅助检索 | 领域谱库建设方向 | 未核对全文的规模和性能；不能称现代自动平台已充分验证 |
| Sims等，2018 [3] | 原文方法、Table1、共洗脱/氘标记实例可核对 | 双证据鉴定、反应失效识别、同位素和修饰边界 | 属于技术建议，不能复制所有历史经验为硬阈值 |
| Pettolino等，2012 [4] | Nature Protocols题录与方法范围明确 | 植物细胞壁组成/连接分析的基础框架 | 具体参数使用时必须核对原文；不能把细胞壁样品制备直接套用纯多糖 |
| Bajwa等，2024 [5] | 正文§3.3–3.5及中性标准分支已核对 | 连贯的衍生化、GC–EI条件和标准比对方法 | 海藻特殊糖另有分支；强酸条件不通用于酸敏感糖 |
| Li等，2026 [6] | 摘要和出版社可见片段确认8糖/92连接/三柱 | 柱特异性保留库和共洗脱分类方向 | 全文/SI的92项未逐条审计，不直接填生产库或阈值 |
| CN119104648A [7] | 说明书与权利要求可核对 | 参照物保留校正、数据库思路 | 软件只见于说明书提议；存在量纲、还原试剂和定量依据问题 |
| CN115406985A [8] | 说明书/权利要求为组成和连接指纹应用 | 单糖组成交叉核验、批次指纹 | 不作为自动PMAA判定算法的验证证据 |

两条前期链接应更正：Sims 2018正确PMID为[29525144](https://pubmed.ncbi.nlm.nih.gov/29525144/)；Li 2026正确PMID为[42035600](https://pubmed.ncbi.nlm.nih.gov/42035600/)。此前使用的29429600、41659749不对应这些论文。

以下内容不进入生产规则：

- 将氨水当作NaBH4/NaBD4的替代还原剂。氨水可作为介质，不能完成所需羰基还原。
- 将RRT比值容差写成分钟。RRT无量纲；RT才带时间单位。
- 将相对保留校正说成能够物理分离异构体。
- 对未活化的游离糖醛酸仅加NaBH4/NaBD4就宣称完成羧基还原。
- 将面积/分子量结果无条件视为准确摩尔量。此法在部分历史文献中确有使用，可保留为明示假设的半定量方法，不能替代响应校准。
- 把标准库制备中的“部分甲基化”移植到未知多糖样品。未知样品必须充分甲基化，否则产生伪连接位点。

Sims Table1流速单位在可核对原件中写作`cm/min`，不能擅自改成`mL/min`当作已确认条件。平台保留原始文本并标记单位疑点；下面采用2024文献明确记录的GC方法作为复现起点。

### 14.2. 样品登记与前处理

#### 14.2.1 必填记录

样本编号、来源和批次；冻干/干燥方式；干基质量及其测量依据；单糖组成及方法/检出能力；糖醛酸、硫酸基和已知天然修饰；盐、蛋白及游离小分子情况；SEC结果；溶解状态；前处理损失；分析目的；仪器方法版本。未测项目标记unknown，不填0。

SEC单峰仅是均一性证据之一。聚合度分布相近并不意味着单一糖链序列。甲基化可分析连接组成，但不能把样本的一切异质性压缩成唯一重复单元。

#### 14.2.2 前处理流程和质量门

| 步骤 | 操作与记录 | 质量门/处理 |
|---|---|---|
| 样本分路 | 测单糖组成、糖醛酸和硫酸基；调查天然O-Me/O-Ac、氨基糖和果糖 | 中性醛糖走N路线；其余进入专项分支；未知修饰提示待查 |
| 去小分子/脱盐 | 已纯化样本按分子量选择透析/超滤；记录膜MWCO、时间、换液和回收 | MWCO不能高到丢失待测组分；保存透出液/滤液用于损失检查 |
| 去杂 | 仅在有证据需要时去蛋白、色素等；记录前后总糖和组成 | 不进行会删去目标糖组分的例行除淀粉/强处理 |
| 干燥 | 冻干后保存密封，记录称量和残余水/盐风险 | 实际质量不能默认全是糖；DMSO与试剂水含量按具体SOP管理 |
| 溶解/分散 | 按N路线DMSO中加热分散；拍照/记录不溶物 | 不溶不能仅靠延长甲基化时间掩盖；评估另一溶解路线 |
| 对照 | 全流程空白、标准多糖、样品独立制备重复；必要时加标 | 后处理分装重复和独立全流程重复分别编号 |

不要把“越无水越好”写成跨方法规则。DMSO、MeI、碱的加料顺序和水含量共同影响反应，文献已讨论特定无水/加料条件导致的副反应。[9] 本方案锁定所选方法顺序；不在缺验证时改变次序或跨方法拼接。

### 14.3. 中性醛糖路线N：可复现的文献起始SOP

以下衍生化条件保持Bajwa等2024中性标准分支与其引用的§3.3流程一致。[5] 约10mg是起始总量，后续分成四份；不应把缩小为1mg的版本自动标记为同等验证。原文的“室温”和“过夜”需要在本地转移时具体化，建议先记录20–25℃、16±1h作为平台试运行设置，并验证后锁定。

| 顺序 | 文献起始条件 | 平台须记录的关键参数 | QC与异常处理 |
|---|---|---|---|
| N1 DMSO分散 | 约10mg样品，2mL DMSO，60℃搅拌过夜；PTFE衬盖玻璃管、N2顶空 | 实际量、时间、温度、试剂批次、溶解状态 | 明显不溶物记录并审核；可能需要专门溶解优化 |
| N2 碱处理 | 冷却室温；新鲜研磨NaOH约200mg，搅拌2h | 加料顺序、温度、时间 | 先NaOH后MeI；不得省略冷却或随意改顺序 |
| N3 甲基化 | MeI 1.2mL，室温避光搅拌3h | 实际体积、起止时间、反应异常 | 全流程空白与标准同时处理；不足时验证补充甲基化 |
| N4 分配清洗 | 冰上加入DCM 3mL；10%乙酸水溶液5mL×2，水5mL×2；保留下层DCM，蒸干 | 每次体积、分相、损失 | 此处只适合中性分支；带电/硫酸化样本不能照此弃水相 |
| N5 分装 | 甲醇8mL溶解，分为4管各2mL，再蒸干 | 每份理论原样当量约2.5mg | 分装不等于独立甲基化重复；预留份用于复测 |
| N6 水解 | 每管2mL 4M TFA，100℃4h；冷却、N2吹干 | 酸浓度、时间、温度、管型及密封 | 酸敏感糖须另法；除酸不充分会干扰后续还原 |
| N7 还原 | 新鲜NaBD4水溶液10mg/mL，2mL，室温搅拌过夜；冰乙酸逐滴淬灭至不再起泡，吹干 | NaBD4同位素规格、批次、浓度、时间 | 醛糖C1引入D；过量还原剂须完全处理；标签未知则不跨标签确认 |
| N8 乙酰化 | TFA 0.25mL＋乙酸酐1.25mL，60℃1h；冷却、蒸干 | 各体积、反应时间、干燥情况 | 与标准比对；强酸可能造成特定糖损失，需做标准回收验证 |
| N9 净化 | DCM3mL；饱和NaHCO3水3mL×2、水3mL×3；有机相经无水Na2SO4，吹干 | 分相和清洗次数、样本损失 | 初始中和放气结束前不密闭；避免水盐进GC |
| N10 复溶进样 | 乙酸乙酯复溶 | 原文未给复溶/进样体积；平台试运行可从0.5mL与1µL开始，须验证线性及不饱和 | 不能把这些补定参数标成原文已验证值；稀释倍数必须入库 |

MeI、强酸、强碱和乙酸酐步骤由受训人员依机构通风、控温及废液SOP执行；NaBD4淬灭、碳酸氢盐洗涤存在放气。原始资料的反应容器与操作条件须在实验室审核后转为正式SOP。

#### 14.3.1 甲基化完全性

FTIR羟基区变化可作支持，不能单独证明所有残基充分甲基化。最低检查组合为：溶解/分相记录、空白、已知标准、全乙酰化副产物、独立制备重复，以及新基质的一轮与补充甲基化比较。

建议试运行比较主要连接组分的一轮/二轮差异是否落在已测重复性范围；在缺少统计分布前可用“变化超过10%相对值或2个百分点”的较大者作为调查触发值，不能作为普适合格标准。补充甲基化后支化候选系统下降、对应少取代衍生物上升，首先怀疑原先欠甲基化。

全乙酰化衍生物也可能来自高度取代、特殊修饰或共洗脱，不以单一峰自动判全批失败。

#### 14.3.2 水解、还原、乙酰化稳健性

在同一批甲基化产物分装上进行水解时间挑战；以4M TFA/100℃/4h为复现点，可选2h、4h、6h作为方法开发条件。该矩阵是本项目设计，选择最终条件应根据标准回收、残余聚合物、关键峰比例及降解产物，而不是只看总峰面积最大。

对还原或乙酰化不完全的疑似样本，用标准及分装样本进行补充反应实验；补充后目标峰继续系统增加则原条件未达稳态。硼酸盐残留、残余酸和水分别记录；如采用甲醇共蒸除硼等额外处理，应登记为新的方法版本并验证回收，不能不留痕迹地插入原文SOP。

### 14.4. 专项分支

#### 14.4.1 糖醛酸路线A

任意已证实的糖醛酸存在都需要评估，不能因低于10%就按“无糖醛酸”处理。目标是先将羧基转为带C6标签的中性糖等价物，再进行连接分析；还原效率必须通过前后组成验证。

可作为方法开发起点的毫克级羧基还原实例来自Wustman等1997的CMC活化流程：[10]

| 步骤 | 已报道起点 | 转移时的质量要求 |
|---|---|---|
| 活化 | 约5mg样本溶于5mL水，pH4.75；水溶性CMC60mg，搅拌约2h，并维持pH4.75 | CMC明确为水溶性碳二亚胺试剂，不是羧甲基纤维素；不得按相同质量改成EDC |
| 还原 | 加冷4M imidazole缓冲液350µL，pH7.0；NaBD4 35mg，5℃搅拌1h | 记录实际pH、温度和试剂纯度；不把普通NaBD4水溶液当游离羧基直接还原方法 |
| 后处理 | 乙酸终止至约pH5.5；约5℃水透析40–50h，冻干 | 根据目标分子量选择膜并核对回收，透析膜规格不能从其他路线机械移用 |

该实例不是对所有酸性多糖、天然甲酯化程度和本平台下游条件的共同验证。正式酸性模块必须使用已知GalA/GlcA来源的标准检查还原前后总量，必要时重复还原。初始目标可设残余糖醛酸相对原始含量≤5%，同时检查对应中性糖增加与总回收；这是项目放行目标，若检出能力不足则不能据此宣称达标。需要区分天然甲酯化与游离羧基时，采用专门的顺序标记路线并重新验证，不从这条总还原路线推算甲酯化位点或程度。[3,11]

羧基NaBD4还原形成C6的6,6-d2；水解后再NaBD4还原则醛糖C1再引入D，两次标签必须分别记录。原中性Gal与GalA还原产物可能共洗脱，含C6的相应离子有+2差异。Sims展示4-Galp/4-GalpA的233/235离子对；必须校正天然同位素、标签纯度及离子串扰，不能以单个235峰直接算GalA比例。[3]

#### 14.4.2 其他专项分支

| 样本特征 | 必须改变或补充的实验 | 平台处理 |
|---|---|---|
| 硫酸化 | 盐型/溶解性处理；必要时原样与经验证脱硫样配对分析；检查脱硫时断链 | 未甲基化位点可能是硫酸取代而非糖苷连接；禁止直接当支化位点 |
| 天然O-Me | 需要区分天然和新增甲基时使用CD3I等标记路线 | 分开记录OCH3/OCD3和相应碎片；普通CH3I数据不确认天然甲基位置 |
| 天然O-Ac | 常规强碱会去乙酰；若研究原位乙酰需专用保留/对照方法 | 常规结果不包含原始乙酰位置的可恢复证据 |
| 果糖/果聚糖 | 酸敏感、C2还原标记、还原产生多个糖醇；专门温和水解 | 不套醛糖C1或单一衍生物规则；配对组分不能误计为两个原残基 |
| 3,6-内醚糖 | 标准TFA流程可能破坏；文献采用还原性水解与常规NaBD4分路 | 不同还原方法的谱库隔离；方法不能互换 |
| 氨基糖 | 明确N-乙酰/N-甲基状态和水解回收 | C2不是普通O-甲基位；旧表把“2-Me”笼统列入O-Me的条目隔离审核 |
| 难溶/强结晶多糖 | 验证分散和充分甲基化；避免只靠强酸补救 | 超出验证范围时仅研究性结果 |

这些分支可在数据库中提前建模，但只有完成专项实测验证的分支才能签发对应的自动确认结果。

### 14.5. GC–EI–MS方法及保留规则

#### 14.5.1 同源复现方法

采用2024文献§3.5作为第一套完整复现方法：[5]

| 参数 | 条件 |
|---|---|
| 色谱柱 | Supelco SP-2380，60m × 0.25mm × 0.2µm |
| 温程 | 55℃起始；20℃/min至170℃；0.3℃/min至190℃；3℃/min至215℃，保持20min |
| 进样口 | 250℃；GC–MS分流比10:1 |
| 载气 | He，恒流0.8mL/min |
| EI/源温 | 70eV，离子源230℃ |
| 四极杆/传输线 | 150℃/280℃ |
| 扫描 | m/z45–350；4.59 scans/s；原文溶剂延迟12min |

这套慢温程适合作为参考复现，升温与保持约101min，另加进样准备/冷却。加速方法属于单独开发任务。原文12min溶剂延迟必须用最早洗脱标准核验；在自建方法中若遮蔽目标峰应修改并登记方法版本。

扫描频率必须按实际峰宽检查，平台拟以最窄待定量峰至少约10个采样点作为初始目标。不得把4.59 scans/s当任意快色谱的固定充分值。主柱可换为实验室已有HP5-ms、DB-23等，但需重建保留库和近邻分离验证；第二柱选择以实际混标的选择性改善为依据。

#### 14.5.2 RT、RRT和RI

`RT`带单位；`RRT = RT(PMAA)/RT(参照物)`无量纲；`RI`须注明算法及同批标准。程序升温与等温的保留指数算法不得混写。内参必须记录化学形式和加入阶段：myo-inositol hexaacetate用于保留参照时，不能把甲基化前加入的游离myo-inositol默认视作同一物质。

文献值只在条件相容时支持候选排序。生产确认使用本方法标准的分布；初始可采用中心±3个标准差并考虑批次漂移和最小测量误差，最终由近邻异构体盲测确定。不能将该窗口转换为“距标准最近即确定”。

Sims Table1的例子：2,4-di-O-methyl Man/Glc在BPX90的RRT约0.826/0.825，而HP5-ms约0.901/0.887。该例说明第二柱可能提供新选择性，不能把这些数值套到SP-2380。其他列如2,3,6-Me3 Glc约0.737(BPX90)/0.759(HP5-ms)也仅为方法特异参考。[3]

### 14.6. PMAA与原连接位点的映射

#### 14.6.1 适用框架和计算规则

对未修饰醛糖，定义`a`为原异头碳，`r`为原成环氧所连的非异头碳，`U`为原残基可具有游离羟基或受体连接的碳位集合，`M`为观察到的O-Me位置。则在充分甲基化、没有其他取代的前提下：

```text
受体连接位置 L = U \ M
PMAA中O-Ac位置 A = {a,r} ∪ L
```

对常见醛糖a=1；原环氧位置在水解开环后也被乙酰化，不能误判为连接位点。对酮糖、氨基糖、硫酸化或带其他修饰的残基，这一简式不能直接使用。

| 框架 | U | r | 说明 |
|---|---|---:|---|
| 醛己吡喃糖Hexp | {2,3,4,6} | 5 | Glcp/Galp/Manp等 |
| 醛己呋喃糖Hexf | {2,3,5,6} | 4 | 环型不同，缺甲基位置解释改变 |
| 醛戊吡喃糖Pentp | {2,3,4} | 5 | Xylp/Arap等 |
| 醛戊呋喃糖Pentf | {2,3,5} | 4 | Araf等 |
| 6-脱氧醛己吡喃糖 | {2,3,4} | 5 | Fucp/Rhap的C6不能作为普通O-Me或O连接位 |

#### 14.6.4 必须保留的多对一来源

4-Arap与5-Araf都可形成相同的1,4,5-tri-O-acetyl-2,3-di-O-methyl arabinitol；CCRC两种来源对应同一谱图文件。[12] 同一己糖骨架的4-Hexp与5-Hexf也可形成相同的1,4,5-Ac3-2,3,6-Me3糖醇。在同位素和立体条件相同时，这属于同一衍生物的不同原始来源。

因此即使与纯标准共进样、全谱一致，也可能只能确认PMAA，不能确认原环型/连接来源。第二根GC柱、EI解卷积或更高匹配分数都不能恢复已丢失信息。应返回原残基候选集合，并由NMR环型证据等解决。

#### 14.7.2 碎片和同位素规则

PMAA的EI解释以糖醇碳链断裂及后续碎裂为基础，记录碎片的原子来源和标签保留情况。若没有足够证据建立完整碎裂机理，规则库可先保留“实测支持离子”，不要给每个峰编造机理。

醛糖NaBD4还原主要在C1加入D，只有保留相应标记的碎片相对NaBH4有相应质量差；不能将整条谱所有m/z统一加1。羧基还原的C6-d2另行处理。需分别保存还原前、羧基还原、异头还原以及CD3I甲基化等步骤。

Sims的Xylp例子展示2-Xylp与4-Xylp相关衍生物在NaBH4路线难以区分，而NaBD4标签可利用189/190等离子差异提供证据；存在共洗脱时仍须校正互相贡献和同位素串扰。[3] 数学上只有响应矩阵可辨识且经过混标验证，才允许分开定量。

#### 14.7.3 两种输入模式

| 输入模式 | 允许的算法 | 禁止的推断 |
|---|---|---|
| qualitative_ion_list：+、红色强峰或简单离子集合 | 标签/骨架相容过滤、按区分力加权的离子覆盖、候选并列 | 把+设为100、用伪强度计算余弦、把未列离子当缺失、输出准确概率 |
| numeric_spectrum：m/z与数值强度 | 背景扣除、适度归一、加权余弦/反向匹配、鉴别离子和离子比检验 | 只看最高分、忽略共洗脱/保留/标签、将全谱分数直接当正确概率 |

初期不设一个通吃所有糖种的“分数≥800就确认”。定性模式权重、数值模式匹配阈值、离子比范围和近邻分差由独立标准验证集确定并版本化。验证前系统可排序，确认仍依赖真实标准及审核。

### 14.8. EI汇总表导入流程

1. 保存原文件、SHA-256、文件名和导入时间；只读解析。
2. 检测工作表、合并单元格、隐藏列、字体/填充颜色、表头和说明文字；展示预览。
3. 核实“红色”的实际语义。仅当原表说明明确时记录为如`reported_gt20pct`；不换算成固定数值强度。
4. 规范PMAA名、原糖名、环型、O-Me、O-Ac、N修饰、NaBD4/NaBH4及来源字段；原始文本同时保留。
5. 校验位点范围：例如普通Glcp不能有C5 O-Me；Fucp/Rhap不能有C6 O-Me；氨基糖C2不作为普通O-Me。
6. 对源表写出的“连接方式”重新做化学映射并比较。冲突进入隔离队列，不以源表列自动覆盖规则。
7. 多来源同名记录保留各自谱图，不把互相矛盾的离子/强度拼成一条“超级谱”。
8. 来源缺失、标签未知、只有离子集合的条目可进入候选库，但不可充当生产确认/定量标准。
9. 人工审核后发布参考库版本；分析记录绑定该版本，后续修改触发差异报告。

最小参考记录：`source_row_id, derivative_name_raw, parent_sugar, ring_form, o_methyl_positions, o_acetyl_positions, nitrogen_modifications, reduction_label, evidence_type, ions, source_locator, method_metadata, review_status`。数值谱另有归一方式、扫描覆盖、测量/提取来源；色谱观测另存method_id和参照物。

当前未收到拟上传的EI汇总表；可见的既有参考资料只用于接口和错误模式设计，不等于本项目数据已经验收。

### 14.9. 原始谱处理与结果判定

#### 14.9.1 数据处理顺序

```text
文件完整性 → 方法/标签检查 → 空白/调谐/饱和检查
→ TIC与EIC构建 → 基线和峰检测 → 共变离子归组/解卷积
→ 数值EI候选 → 同方法保留核查 → 结构映射与组成一致性
→ 定量与样本QC → 人工复核 → 版本化报告
```

保留原始扫描和所有处理参数。基线校正不得消去真实低丰度鉴别离子；质心化/取整容差依仪器质量精度验证，不能在高分辨数据上直接无记录地取整数。单位、保留时间轴和强度积分要与原厂软件在测试文件上核对。

共洗脱模型可写为`Y(t,m) ≈ Σ A_k(t) S_k(m) + B(t,m)`。要求非负、合理峰形、有效残差和稳定解。如果两组分没有可区分的谱/保留信息，模型并不可辨识，必须保持组合峰；不能因算法返回两个系数就宣称物理分离成功。

#### 14.9.2 判定状态

| 维度 | 状态与含义 |
|---|---|
| qc_status | passed / warning / failed / not_assessed |
| derivative_identity_level | confirmed：同方法真实标准、完整EI、保留和质量门支持；probable：强支持但确认条件不齐；candidate：证据有限或并列；unknown：没有可辩护候选 |
| residue_mapping_level | resolved：适用前提下唯一；ambiguous：同一PMAA有多个来源；unsupported：缺少映射适用条件 |
| quantification_level | calibrated_molar / semiquantitative / area_only / unavailable |
| review_status | automated / human_reviewed |

`confirmed`针对衍生物身份，不自动将原残基映射变成resolved。仅EI汇总表的候选上限不因高分突破；批次QC失败则禁止正式报告签发，但保留研究性结果。

### 14.10. 定量与样本级检查

#### 14.10.1 校准定量

优先使用与实际检测器、积分方式相同的PMAA标准校准。内标模型可定义：

```text
y_i = A_i / A_IS
x_i = n_i / n_IS
y_i = a_i + b_i*x_i
n_i = n_IS * (y_i-a_i)/b_i
mol%_i = 100*n_i / Σ n_j
```

`A_i`是与校准一致的TIC、FID或选择离子面积，不能混用。内标加入最终样品只评价进样/检测，不验证前处理回收；全流程损失由独立标准制备和过程对照评估。天然同位素及标记串扰需在进入定量前校正。

未校准可以报告面积百分比；历史面积/分子量换算另标`semiquantitative`并注明假设，不作为准确mol%。组合峰缺少可分解响应时不强行分摊。未识别峰只能报告其可测面积贡献，不能编造未知组分的摩尔占比。

分母明确写为“已鉴定且在校准范围内的PMAA总摩尔量”；不能让这种归一化看起来覆盖了原样所有残基。分别报告未识别面积比例、低于LOQ组分、未覆盖的专项糖和样本回收。

#### 14.10.2 端基—支化检查

对无环、普通单异头连接、所有残基和还原端均正确计入的糖链森林，设`n_k`为有k个非异头受体连接位的残基数，C为链数，则：

```text
n_0 = C + Σ(k-1)*n_k   (k≥2)
```

当聚合度高、主要为双受体支化时，才近似出现端基数与支化点数接近。低聚物、还原端处理、环状链、双异头连接、修饰、欠甲基化和定量偏差都会改变解释。平台把平衡偏差作为调查信号，不硬性要求所有样品端基:支化=1:1，也不为了“闭合”篡改峰面积。

单糖组成比较需统一中性/糖醛酸还原折算、回收和分母。PMAA提示微量Gal而组成未检出时，先看组成分析的检出限和水解回收，不能立即删掉Gal候选。

### 14.11. 歧义处理表

| 情形 | 可解决手段 | 不能做的事 |
|---|---|---|
| Glc/Gal/Man同连接EI相似 | 本地同柱标准、相容组成、第二柱 | 单靠EI给糖种唯一判定 |
| 同糖不同连接共洗脱 | 诊断EIC、混标校正、第二柱或经验证解卷积 | 重复分配共享离子的全部面积 |
| 相同PMAA来自不同原环型/连接 | NMR环型/独立结构证据 | 声称换柱可区分同一化合物的来源 |
| D/L对映来源 | 独立手性分析或来源确证 | 非手性GC–EI直接给D/L |
| α/β来源 | NMR/酶学等独立证据 | 从PMAA峰形/保留补异头构型 |
| NaBH4与NaBD4混库 | 按原子标签分库、重新测标准 | 全谱统一+1修正 |
| 糖醛酸还原物与中性糖共洗脱 | C6标签离子及同位素响应矩阵 | 仅凭RRT分开 |
| 欠甲基化伪支化 | 补充甲基化、标准/回收检查 | 将额外乙酰位全部解释为真实连接 |
| 硫酸/天然修饰占位 | 专项对照、标记及NMR | 直接套无修饰糖补集公式 |
| 只有少量离子/没有保留 | 多候选报告，列补测需求 | 编造谱强度或准确置信度 |
