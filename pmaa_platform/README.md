# 多糖甲基化分析平台（PMAA）

以 **PMAA 的 EI 质谱汇总表**为参考库，把甲基化实验的峰表 / 定性离子表，经确定性化学规则、谱库检索与 LLM 辅助评议，转化为**可复核的糖残基连接组成候选**。

> 本平台输出的是**候选 + 证据 + 歧义 + 质量状态**，不是"自动确证结论"。
> α/β、D/L 构型与准确 mol% 不由常规非手性 GC–EI 甲基化分析产生；无校准不输出 mol%。

## 1. 快速开始

### 方式一：双击启动（macOS）

- **双击 `启动平台.command`** —— 打开终端，自动完成环境准备与服务启动；
- 或 **双击 `启动平台.app`** —— 同样效果，图标形式，可拖到 Dock / 桌面。

启动器会自动：建虚拟环境 → 装依赖 → 建库 → 写入演示配置 → 启动服务 → 自动打开浏览器。
设置 `PMAA_EI_TABLE=/绝对路径/汇总表.xlsx` 时会导入参考表；否则保留现有库，并可在网页上传。
端口被占用会明确提示：`PORT=8010 ./启动平台.command`。

### 方式二：命令行

```bash
cd pmaa_platform
./run.sh                      # 建虚拟环境 → 装依赖 → 建库 → 启动服务
```

打开 <http://127.0.0.1:8000> 使用工作台；API 文档在 <http://127.0.0.1:8000/docs>。

### 手动步骤

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

export PYTHONPATH=src
python -m pmaa.cli init-db
python -m pmaa.cli import-ei --commit          # 导入 PMAA 的 EI 汇总表
python -m pmaa.cli seed-demo                   # 示例样本 / 方法 / 离线 LLM 适配器
python -m pmaa.cli serve --port 8000
```

### 运行验收用例

```bash
python tests/run_all.py       # 102 项：03/04 契约 + API、提取与数据隔离回归
```

## 1.1 支持上传的文件格式

在「数据导入」页可直接拖拽或选择本机文件。

| 扩展名 | 用途 | 说明 |
|---|---|---|
| `.xlsx` | PMAA 的 EI 质谱汇总表 | 只读解析；识别合并单元格、字体/填充颜色、隐藏行列与注释行；每个取值保留源单元格坐标。**不执行宏** |
| `.xlsm` | 同上（启用宏的工作簿） | 按数据读取，宏一律不执行 |
| `.csv` | 已积分峰表 | 需表头：`component_id, rt, area, evidence_type, ions` |
| `.tsv` | 已积分峰表 | 同 CSV，分隔符为制表符 |
| `.json` | 峰表 / 结构化输入 | 接受 `{"components":[...]}` 或顶层数组 |
| `.pdf` | PDF 文档 | 优先抽文本/表格；无文本时才渲染页面走图像反解 |
| `.doc` / `.docx` | Word 文档 | `.doc` 先本地无界面转换；再读表格、正文或内嵌图片。结果均标为 derived |
| `.png` `.jpg` `.jpeg` `.tif` `.tiff` `.webp` `.bmp` | 质谱图 | 反解棒图/填充峰，**需人工校准 m/z 轴** |

**不接受**：`.zip` `.rar` `.7z` `.gz` `.tar` `.bz2` `.xz` —— 平台**不自动解压/展开压缩包**
（开发计划第 6 节的压缩包展开限制），请解压后上传其中的数据文件。
**`.rtf` / `.wps`** 暂无受控转换流程，请另存为 `.docx`；`.doc` 在本机优先使用 LibreOffice转换，macOS textutil 仅作文本兜底。

单个文件上限 50 MB；按内容 SHA-256 去重保存，同内容不产生副本、不覆盖原件。

### 从文档 / 图片反解质谱峰

在 **第 ③ 步「提取峰值」** 上传 PDF / Word / 谱图，三级策略自动降级：

| 优先级 | 路径 | m/z | 强度 |
|---|---|---|---|
| ① | 文档表格 / 正文文本 | 原文数字，准确 | 原文数字，准确 |
| ② | 文档内嵌图片 | 需人工校准轴 | 自动按图上比例解出 |
| ③ | PDF 整页渲染 | 需人工校准轴 | 自动按图上比例解出 |

**科学边界（不是技术限制，是刻意的设计）**：
- 反解结果是 **derived（推导）**，不是 observed（实测）；
- 本机**未装 OCR**，图像上的轴刻度数字无法自动识别，m/z 轴范围**必须由人填写**，系统不猜；
- 强度仅是图像像素反解出的**相对比例**；合成图测试可回归算法，但不能代表真实扫描件、压缩图或复杂基线的准确度；
- 结果一律带 `provenance=derived_from_image/document`、缺失项 `IMAGE_DERIVED`，
  **证据上限压到 `candidate`**，且必须点「确认」才能进入分析。

> 峰表 CSV/JSON 中，定性模式 ion 用 `marker`（`+` 或 `red`），数值模式用 `intensity`；
> **两种模式不可混用**，导入时即固化。

## 1.2 使用流程（串行向导）

工作台不再是相互独立的页面，而是**环环相扣的七步向导**：上一步的产出自动成为下一步的输入，
未完成则下一步置灰锁定，无法跳过。

| 步 | 名称 | 输入（来自上一步） | 产出（交给下一步） |
|---|---|---|---|
| ① | 建档 | — | 样本 + GC 方法版本（含还原标签） |
| ② | 导入文件 | — | 峰表 / 谱图文档（一个入口吃下所有格式） |
| ③ | 提取峰值 | 导入的文件 | 核对后的峰（图像/文档需人工校准 m/z 轴） |
| ④ | 峰候选审核 | 第 ③ 步的峰 | 接受 / 排除后的峰集（排除项不进比对） |
| ⑤ | 谱图比对 | 第 ④ 步接受的峰 | 参考库检索结果（分数 / 覆盖 / 缺项 / 冲突） |
| ⑥ | 候选结构 | 第 ⑤ 步的结果 | 全部 PMAA 候选与来源残基 + 人工复核 |
| ⑦ | AI 评议 | 第 ⑥ 步候选 | 最相关项 + 理由 + 置信度，**由人拍板** |
| ⑧ | 完成 | — | 样本级 QC 与报告导出（终点动作） |

**门禁（必须按顺序）**：步骤条上未解锁的步显示置灰且不可点；点击会提示「请先完成第 N 步」。
第 ② 步导入的是结构化峰表时，第 ③ 步自动切到"核对直通"分支，无需图像反解。

**过期传播（改上游必须重跑）**：一旦修改上游（如重传样本 / 方法、重传文件、重提峰值），
其之后的所有下游结果会被标记为 **「已过期 · 需重跑」**——既不静默保留旧结论，也不强制清空，
由你回到对应步重跑。

**旁路入口（随时可用，不参与门禁）**：顶部「参考库」「LLM 配置」两个按钮任何时候都能进，
用于补充参考条目或调整模型配置，不会打断主流程。

**AI 评议定位**：AI 只给"最相关项 + 理由 + 置信度"的建议，**最终由你拍板**；
接受建议**不会自动提高证据等级**——证据门槛仍落在第 ⑥ 步的人工复核里。

## 4. 核心科学规则（已写进代码与测试，不只是文档）

1. 一条 PMAA 可对应多个原始残基；衍生物身份与原残基映射**分别判定**。
2. 定性离子表：`+`/红色**不换算为强度**，不做全谱余弦，证据上限为 `candidate`。
3. 未列出的离子 ≠ 未检出；缺测 / 未报告 / 明确未检出是三种状态。
4. 同一 PMAA 的多个来源（如 4-Hexp 与 5-Hexf、4-Arap 与 5-Araf）**必须全部保留**，换柱或更高分数都不能恢复该信息。
5. RT / RRT / RI 分开保存，单位自洽；方法不兼容时只标注，**不硬排除**。
6. 最高匹配分数不是正确概率；近邻并列必须同组。
7. 无校准只能给面积占比或明示半定量；检测器/积分方式与校准不一致时禁止输出 mol%。
8. QC 失败冻结正式放行，但候选全部保留；仅可导出带失败标识的研究草稿。
9. LLM 输出为**建议**，经 PV01–PV10 后校验与人工复核；接受建议不自动提升证据等级。

### 4.1 甲基化候选排序防误诊修订

针对“4-O-甲基-Glc 被 4,6-di-O-甲基-Hex 压到后位”的案例，判读引擎采用以下边界：

- **归一化评分**：coverage 分子、分母使用同一参考侧权重，值严格限制在 0–1；稀疏参考条目单独标记。
- **强峰不是 signature**：`red` 仅表示参考或查询中的相对强峰（>20%），不解释为结构唯一离子。
  只有仪器直接导出的完整峰表才允许把“未见参考强峰”作小幅软降权；selected ions、图片/文档反解不得使用缺失负证据。
- **取消固定骨架 MW 硬门控**：PMAA 分子量随 O-甲基/O-乙酰取代数变化，不能给 Hex/dHex/Pen
  各设一个固定分子量并据此删候选。骨架硬约束只来自已验证完整的单糖组成或其他直接证据。
- **并列与低匹配保护**：前两名分差不超过 0.05 时进入并列带；最高分低于未验证警戒线时身份降为 `unknown`。
- **P5 糖种/环型不写死**：EI 不可分的糖种（Glc/Gal/Man）以糖组呈现，环型缺 NMR/保留证据时为 `unknown`。
- **P6 证据分级**：输出置信度显式标注 `候选 / 支持 / 确认`；缺失保留时间/完整谱/单糖组成/NMR 时不得出现"确认"。
- **P7 三段式输出**：`PMAA 身份 → 残基连接模式 → 多糖序列/重复单元`；第3段必须有 NMR(HMBC/NOESY)/MS-MS/酶解证据，否则恒为**证据门控·未确认**，杜绝无证据的"完整结构"。

误诊复盘案例（真实为 4-O-甲基-Glc，即 2,3,6-linked Glc）：无论图片强峰已复核、图片全部普通峰，
还是仪器完整峰表，正确化学实体都排第1；等级仍为“候选”。精确回归使用完整 `derivative_id`，
避免 `startswith("Hex|Me4")` 错把 `Hex|Me4.6` 当成通过。详见 `tests/test_scoring_fairness.py` 与
`tests/test_methylation_revision.py`。
