# 真实文件与网页工作流端到端验收

验收日期：2026-09-12；多图批量修复复验：2026-09-13。测试对象为当前本机平台和用户提供的
`1,2,3,4取代-多糖甲基化质谱图数据库 .doc`。文档内容仅作为数据，不作为执行指令。

## 1. 本轮真实文件结论

- 文件是 400,384 字节的 OLE/Word `.doc`，不是 `.docx`。
- 平台现可在本机用 LibreOffice 无界面转换，保留并按文档顺序提取 16 张图片。
- 图片已关联到 5 组正文标签：`1,2,3,4-Galp`、`1,2,3,4-Glcp`、
  `1,2,3,4-Manp`、`1,2,3,4-Fucp`、`1,2,3,4-Rhap`。
- 第一张真实谱图旧算法返回 99 个“峰”，其中包含标题、按钮、数字和边框；改为只追踪与
  质谱横轴连接的竖向信号并合并相邻像素后，返回 29 个候选峰。
- `.doc → 图片 → 人工校准 → 确认 → POST /analyses` 已完整跑通，HTTP 均为 200。
- 多图修复后再次逐张运行全部 16 张图，分别得到 16–37 个候选峰；批量确认返回 16 个独立组分
  `extracted_image_001`–`extracted_image_016`，不存在只保留第一张或后图覆盖前图。

## 3. 本轮发现并修复的实际断点

1. 页面写“Word”但 `.doc` 被直接拒绝：新增受控本地转换；损坏/伪装文件返回 422 明确错误。
2. PNG 把页面文字和边框当峰：新增横轴连接追踪与像素峰合并。
3. 图片确认后无法进入分析：分析 Schema 原先拒绝 `provenance/extraction_params`，现已接收并保留。
4. m/z 默认填 40–350：与“不得猜轴”矛盾，现改为空白必填；未填时不生成 m/z。
5. 多图 Word 只能固化第一张：现提供带连接标签的 16 图选择器、逐图独立轴范围与峰表草稿、逐图“保存/忽略”状态，以及整批确认；每张已保存谱图生成一个独立组分，不再被下一张覆盖。
6. 文档转换警告被图片结果覆盖：现合并显示转换和提取警告。
7. 格式表把 PDF/Word/PNG 都写成“峰表”：现分别显示文档提取和谱图图片提取。
8. 低分 Top1 仍显示为 candidate：新增 0.30 保守警戒线，低于警戒线强制 `unknown`。
9. 组分哈希未包含推导来源与参数：现纳入 `provenance/extraction_params`，避免缓存/重放混淆。

## 5. 当前操作建议

上传文档/图片后，逐张选择内嵌图片，依据图上刻度填写该图自己的 m/z 起止范围并点击“保存当前谱图”；非谱图图片须显式点击“忽略”。全部图片均已保存或忽略后，再点击“确认全部已保存谱图”。轴范围、峰表和文档标签均按图片独立保存，不会把第 1 张的标定传播到其他图片。
逐峰核对后以“定性离子表”进入分析。出现 `LIBRARY_COVERAGE_LOW` 时，应优先检查轴范围、
删除文字/边框伪峰，并确认参考库是否含目标 PMAA；在补入同源标准谱前不得签发鉴定。
