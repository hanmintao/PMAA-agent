# 架构说明

## 1. 总体架构

采用**模块化单体**：Python 分析核心 + FastAPI API + 无构建前端 + SQLAlchemy 数据层。
不拆微服务——首个可交付版本的服务边界尚不稳定，微服务只会增加分布式调试成本而不带来收益。

```
┌─────────────────────────────────────────────────────────────────────┐
│  Web 工作台（web/：原生 ES + CSS，六步流程 + 参考库 + LLM 配置）        │
└───────────────────────────────┬─────────────────────────────────────┘
                                │  REST /v1
┌───────────────────────────────▼─────────────────────────────────────┐
│  API 层  api/  —— 路由、请求校验（extra=forbid）、统一错误码            │
├─────────────────────────────────────────────────────────────────────┤
│  导入层 ingest/    化学层 chemistry/   检索层 search/                 │
│  · xlsx 只读解析   · 5 种骨架框架      · 定性离子检索（IDF 加权）      │
│  · PMAA 名解析     · L = U \ M 映射    · 数值谱加权余弦 + 反向匹配     │
│  · 峰表导入        · 位点相容性校验     · RT/RRT/RI 方法相容性         │
├─────────────────────────────────────────────────────────────────────┤
│  分析层 analysis/   —— 候选聚合 → 五维状态 → 证据包 → 定量 → QC        │
├─────────────────────────────────────────────────────────────────────┤
│  LLM 层 llm/       —— 适配器 → 网关（超时/重试/预算/缓存）→ 后校验      │
├─────────────────────────────────────────────────────────────────────┤
│  数据层 data/      —— ORM 模型 + 仓储封装（统一连接/事务/异常）         │
├─────────────────────────────────────────────────────────────────────┤
│  报告层 reporting/ —— 版本化快照 + HTML/JSON 导出                     │
└─────────────────────────────────────────────────────────────────────┘
                                │
                    SQLite（默认且已验证）/ PostgreSQL（迁移路径待验证）
```

## 2. 数据流转

```
① EI 汇总表（xlsx）
      │ 只读解析 → 单元格坐标 + 字体色 + 合并区 + 注释语义
      ▼
   ImportRowResult（每行：状态 / 推导连接位 / 源表连接位 / 冲突 / 说明）
      │ 化学复核：骨架推断 → 位点相容性 → 与源表连接方式比对
      ▼
   ReferenceRecord + ReferenceIon   ←→   Derivative + ResidueMapping（多来源）
      │
② 峰表 / 定性离子表
      │ 解析（两种模式互斥，混用即报错）
      ▼
③ 分析流水线
      检索（定性 IDF 加权 / 数值加权余弦）
        → 按化学实体聚合（Gal/Glc/Man 同一 PMAA 合并，标签退回骨架级）
        → 保留证据相容性检查
        → 反查该实体的全部原残基来源
        → 五维状态判定 + 证据上限
        → 缺失证据 / 冲突 / 下一步补测建议
      ▼
   ComponentResult（analysis_id、候选、证据、歧义、定量、QC）
      │
      ├──→ ④ 证据包（服务端构建并冻结）→ LLM 网关 → PV01–PV10 后校验 → 人工审核
      │
      ├──→ ⑤ 样本级 QC → 正式报告门（失败即冻结）
      │
      └──→ ⑥ 报告快照（输入哈希 + 库/规则/方法版本）→ HTML / JSON
```

## 3. 与 EI 数据库的集成方案

### 3.1 源文件结构（实测）

| 项 | 实测结果 |
|---|---|
| 工作表 | `Sheet1`（Sheet2/3 为空） |
| 布局 | 行 = PMAA 衍生物（57 行），列 = m/z（63 列，59–275），A 列名称，BM 列"连接方式" |
| 分组行 | R2 六碳糖 / R45 6-脱氧己糖 / R54 五碳糖 |
| 注释 | R64 合并单元格 `C64:BL65`，声明：红色 = 相对强度 >20%；"+" = 有该信号；五碳糖只统计呋喃糖；使用 NaBD4 还原 |
| 颜色实测 | 红色字体（FFFF0000）391 个，普通 "+" 173 个，合计 564 |
| 糖种覆盖 | Gal / Glc / Man（含 7 条 `2NAc` 氨基糖）、Fuc / Rha、Ara |

### 3.2 集成要点

1. **只读 + 可追溯**：每个离子都带 `source_cell`（如 `Sheet1!R32X`），参考记录带 `source_row_id`，
   源文件记录 SHA-256 —— 每个生产条目都能回到源文件的具体单元格。
2. **颜色只记语义**：红色 → `intensity_class = reported_gt20pct`，**不换算成数值强度**；
   原表未给出该声明时自动降级为 `reported_present`。
3. **空单元格不生成离子行**：定性表没有扫描覆盖与检测阈记录，空 = `not_reported`，不得当"未检出"用于排除。
4. **化学复核后再入库**：源表"连接方式"列按 `L = U \ M` 重新推导并比对；
   冲突进隔离队列（本次 57 行**零冲突**，见下）。
5. **多来源分表**：`derivatives`（化学实体，主键为规范键，**不含"原残基名称"**）
   与 `residue_mappings`（同一实体多行）分开，天然表达"同一 PMAA 多个来源"。
6. **氨基糖分支**：`(2NAc)` 表示 C2 为 N-取代，解析时把 C2 从 O-甲基位剔除，
   并按 `U \ N位` 计算连接位——修正后 7 条氨基糖记录的推导结果与源表标注**完全一致**。

### 3.3 导入结果

```
57 行 → 入库 50 · 氨基糖分支隔离 7 · 错误隔离 0 · 连接方式冲突 0
36 个化学实体，其中 14 个存在多个原残基来源（多对一歧义）
```

## 4. 关键设计决策

| 决策 | 理由 |
|---|---|
| 化学实体主键 = `(骨架, O-Me, O-Ac, 标签)` 规范键，不含糖名 | 同一 PMAA 可来自不同糖种/环型；用"原残基名"当主键会人为制造唯一解 |
| 定性 / 数值两个评分器完全分离 | 03 契约 A01：把 `+` 当 100 再算余弦是伪证据 |
| 检索先按记录召回 20 条，再按化学实体去重取前 5 | 计划 13.3 的预算按**不同 PMAA 实体**计，不是按记录行计 |
| 定性评分 = 加权几何均值，查询侧召回权重 0.7 | 定性表只报少量离子；若以参考覆盖率为主，离子数少的条目会靠小分母刷分 |
| 同一实体被多个糖种记录支持时，标签退回骨架级（如 `1,6-Hexp`） | 常规 EI 不能区分 Glc/Gal/Man，写死糖名是越界 |
| 数据层用仓储封装，SQLAlchemy 隔离大部分方言差异 | PostgreSQL 仍需安装驱动并验证迁移、JSON 行为、约束/并发和备份恢复；不能只改 URL 就视为生产就绪 |
| 前端无构建步骤 | 研究用平台优先保证"能跑起来"和易审计，避免 Node 工具链成为部署门槛 |
| LLM 默认提供 Mock 适配器 | 无密钥环境下全链路（证据包 → 评议 → 后校验 → 审核 → 报告）仍可完整验证与回归 |

## 5. 状态模型

五个状态维度**独立保存**（计划第 5 节）：

| 维度 | 取值 |
|---|---|
| `qc_status` | passed / warning / failed / not_assessed |
| `derivative_identity_level` | confirmed / probable / candidate / unknown |
| `residue_mapping_level` | resolved / ambiguous / unsupported |
| `quantification_level` | calibrated_molar / semiquantitative / area_only / unavailable |
| `review_status` | automated / human_reviewed |

`confirmed` 只描述**衍生物身份**，不会自动让原残基映射变成 `resolved`。
"PMAA 已确认、原残基仍有两种环型候选、只能半定量"是合法且常见的结果。

## 6. 可重复性

- 报告快照保存 `input_hash` + `library_version` + `rule_version` + `method_version`；重跑生成新版本，不改写历史。
- 证据包内容哈希（**不含随机 bundle_id**）用作 LLM 缓存键，配合 provider 配置版本、提示词哈希、Schema 版本。
- 历史报告读取已保存的 LLM 响应；重新调用模型生成**新的**评议版本，不冒充旧结果。
