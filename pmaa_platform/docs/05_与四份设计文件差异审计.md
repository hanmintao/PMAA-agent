# 当前平台与四份设计文件的差异审计

审计日期：2026-09-12。审计对象为当前 `pmaa_platform` 的后端、网页、SQLite 数据、自动化测试，
对照四份设计文件逐项核验。结论分为“已实现”“部分实现”“未实现”和“必须经实验验证”，
避免把代码存在、测试通过和科学性能验证混为一谈。

## 一、结论摘要

平台已经覆盖甲基化结果判读的核心原型链路，但与完整计划仍有明显差距。不存在“其余工作
全部只卡在湿实验”的情况：原始 GC–MS、报告 PDF/XLSX、权限、备份恢复、异步任务、校准数据管理、
真实知识检索和真实 LLM 评测仍属于未完成的软件或软件＋验证工作。新增的 PDF/DOCX/谱图图片
提取只是便利的数据恢复入口，不能代替原始 GC–MS 数据处理，也不能解决色谱共洗脱。

本轮审计发现并修复了会影响科学结果或数据隔离的缺陷：

1. 多 PMAA 候选时错误生成“所有 PMAA × 所有残基来源”的笛卡尔组合。
2. 实际歧义成员 ID 与发给 LLM 的候选 ID 不一致，导致并列来源约束失效。
3. LLM 评议和人工决定按通用 `component_id` 查询，可能串入另一个分析的同名峰。
4. OpenAI Responses 成功状态 `completed` 未规范化为 `stop`，真实成功响应会被误判失败。
5. 未完整处理 Responses 的 `incomplete` 和结构化 `refusal`。
6. QC 只写状态、不保存输入和检查明细；报告无法重放 QC 依据。
7. 报告漏掉峰离子、方法快照和人工复核轨迹。
8. 前端用 GET 调用仅支持 POST 的 HTML 导出端点，实际返回 405。
9. HTML 报告对用户文本缺少转义。
10. 路径中写死个人电脑上的源文件位置，影响迁移和隐私。
11. 完成度文档把 23 个任务写成“17 完成＋5 部分＋4 未开始”，算术合计为 26。
12. 文档/图片中抄出的数值峰表曾被标成 `full_acquired_range`；现强制标为 `selected_ions`，
    人工确认也不能把推导数据升级为仪器完整谱。

上述问题均已修复或更正，并增加对应回归测试；当前为 102/102 通过。

## 二、与四份文件的逐项差异

### 1. `01_开发执行计划.md`

| 计划要求 | 当前状态 | 差异/处理 |
|---|---|---|
| M01 样本、方法、PreparationBatch | 部分实现 | 本轮补上 N1–N10 制备记录 API、网页入口、分析绑定、LLM 证据包和报告归档；仍缺附件、电子签名和锁定方法的编辑拒绝 |
| M02 XLSX/CSV/JSON 导入 | 已实现核心路径 | 当前只对一份 57 行 xlsx 和构造峰表回归；PDF/DOCX/图片为附加推导入口，需真实文档集验证 |
| M03 版本化参考库 | 部分实现 | 有来源与审核状态；没有正式的 library release/version 实体及前端审核工作流 |
| M04 PMAA 映射 | 已实现于限定骨架 | 多来源保留已修复；糖醛酸、硫酸化、果糖等仍不能自动签发 |
| M05 定性/数值 EI | 部分实现 | 定性检索可用；当前 57 条库没有完整数值谱，数值算法只通过构造测试 |
| M06 RT/RRT/RI | 部分实现 | 数据模型和相容性检查存在；生产库保留观测为 0，网页也无录入/图形比较 |
| M07 TIC/EIC/峰提取/解卷积 | 未实现 | 这是解决共洗脱问题的关键缺口，不能用当前峰表模式替代 |
| M08 校准定量与 QC | 部分实现 | 有函数和手工 QC；没有校准曲线数据库/API、LOQ 工作流或标准实测 |
| M09 三栏复核 | 部分实现 | 算法、LLM、人工页面分开；尚不能在一屏点击定位每条证据 |
| M10 HTML/PDF、XLSX/JSON | 部分实现 | JSON/HTML 已修正；这里缺的是**报告导出** PDF/XLSX，和新增的 PDF 输入解析不是一回事 |
| M11–M13 LLM | 部分实现 | 核心网关、Schema 和后校验存在；文献检索、真实 API、持久化费用限额、盲测对照未完成 |
| P4–P6 | 未开始 | 原始数据、盲测、备份恢复、正式发布均未完成 |

主计划原第 15 行“软件尚未实现”属于历史状态，现已更新为当前原型状态；计划内容本身继续作为
目标范围，不应反向改写为“已经完成”。

### 2. `02_实验与判读技术规范.md`

规范中的科学边界总体被代码遵守：定性 `+` 不伪造成强度、未列离子不等于未检出、
NaBD4/NaBH4 标签隔离、`L = U \\ M`、环型多来源保留、无校准不报 mol%。

尚未形成闭环的部分：

- N1–N10 现在可以原样登记并进入证据包，但平台没有自动判断各实测参数是否偏离已签认 SOP；
- 一轮/补充甲基化、2/4/6 h 水解挑战、还原/乙酰化补充反应尚无成组比较页面；
- FTIR、全乙酰化副产物、空白、标准、独立制备的证据尚未自动聚合；
- 4-Arap/5-Araf 等同一 PMAA 来源歧义可保留，但仍需 NMR/外部环型证据才能解决；
- 糖醛酸 C6 标签、天然同位素校正、硫酸化、果聚糖和 3,6-内醚糖仍是专项分支。

### 3. `03_数据契约与验收用例.json`

A01–A24 对应的核心规则已有直接或组合测试，但自动化测试中还包含扩展回归，不能把测试数理解成
独立科学验证样本数。本轮新增了实际数据流级的候选关联、报告重放、QC 持久化、制备记录
和跨分析隔离测试。

需在下一版契约增加的字段/约束：

- `candidate_residues.derivative_id`，显式绑定 PMAA 与原残基来源；
- PreparationBatch 的 N1–N10 结构化 Schema、SOP 版本和偏差状态；
- calibration、blank、standard、replicate-set 实体；
- 报告格式能力声明，不再用文案暗示未实现的 PDF/XLSX；
- analysis/project/tenant 的隔离键和唯一约束；
- 数据库迁移版本，不能只依赖 `create_all()`。

### 4. `04_LLM接口契约与验收用例.json`

结构化输出、候选覆盖、证据 ID、歧义保留、α/β 与 D/L 越界、无校准 mol%、回退与归档的
代码路径已实现。实际差异包括：

- 原先 Responses 的 `completed` 状态不被网关接受；本轮已修复并覆盖 completed/incomplete/refusal；
- 原先实际歧义候选 ID 不一致；本轮已修复；
- 幂等键和报告查询原先可能跨分析复用；本轮已按 analysis/provider 隔离；
- provider “测试”端点目前只是配置/能力声明检查，不是真实联网探测；
- `_estimate_cost()` 仍固定返回 0，预算只存在进程内，重启或多 worker 后不可靠；
- 未执行真实模型的重复稳定性、盲测误确认率、有/无 LLM 审核耗时对照；
- 现有语义越界检查含正则启发式，不能代替专家复核。

## 三、本轮代码改进

| 改进 | 结果 |
|---|---|
| PMAA—残基显式关联 | `CandidateResidue` 增加 `derivative_id`，证据包不再构造错误组合 |
| 歧义 ID 一致性 | 实际分析产出的 ambiguity 成员可以被 PV02 强制同组保留 |
| 数据隔离 | LLM、人工决定和报告按 analysis 内部组件键隔离 |
| OpenAI Responses | 正确处理 completed、incomplete、refusal；不再虚报 seed 支持 |
| 失败归档 | HTTP 错误保留原响应，网络错误进入受控回退路径 |
| 实验记录 | 新增 `/samples/{id}/preparations` GET/POST；N1–N10 可绑定分析并进入 LLM 事实 |
| QC 可重放 | 保存原始 QC 输入、逐项检查、阻断项和放行状态 |
| 报告完整性 | 加入方法快照、谱离子、制备记录、QC 明细和人工审核轨迹；历史报告可按 ID 读取 |
| HTML 导出与安全 | 前端改为 POST 获取 HTML；用户文本进行 HTML 转义 |
| 可迁移性 | 移除个人绝对路径，优先使用环境变量、现有上传或网页上传 |

## 四、下一步优先级

### P0：在让真实样本进入平台前

1. 实现账号、角色和项目/租户隔离；限制 CORS；保护 provider 配置与原始文件。
2. 建数据库迁移、自动备份和实际恢复演练；补唯一约束与并发测试。
3. 建立校准曲线、空白、标准品、独立重复实体及 API，而不是只传一组 QC 数字。
4. 增加完整数值 EI 谱导入与本地标准审核工作流。
5. 实现报告 PDF/XLSX 导出，或明确产品范围只承诺 HTML/JSON。

### P1：解决用户最关心的重叠峰问题

1. 选择一个仪器来源，完成厂商格式→mzML 的强度、时间、扫描数对照。
2. 实现 TIC/EIC、峰边界、背景扣除和原始/处理谱并排回看。
3. 对共洗脱先输出“组合峰＋不可辨识”，再用标准混合物验证解卷积；不能把算法拆峰当真实分离。
4. 加同柱 RI/RRT 标准库及第二柱正交证据；用近邻异构体混标确定阈值。

### P2：让 LLM 具备可评价的辅助价值

1. 用真实服务商做不含样本的连接探测与小规模脱敏调用测试。
2. 将费用、调用次数和幂等状态持久化，支持多进程部署。
3. 建专家参考盲测集，比较无 LLM 与有 LLM 的候选覆盖率、误确认、冲突检出和审核耗时。
4. 只在 LLM 确有增益且不提高误确认率时扩大使用；否则保留为解释/补证建议工具。

## 五、当前可用范围

可以使用：限定中性醛糖参考表导入、定性 EI 候选检索、PMAA 甲基模式到连接候选映射、
歧义保留、人工复核、Mock LLM 流程、研究型 JSON/HTML 报告。

不可声称：自动确定唯一多糖结构、解决所有重叠峰、α/β 或 D/L 判定、准确 mol%、本地标准确认、
真实 LLM 已验证、V1.0 正式放行。
