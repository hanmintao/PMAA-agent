# 假设与未决项

开发计划中未明确、或源数据未直接给出之处，本实现按下列假设处理。
每条目标注**假设内容、理由、以及如果不成立该如何调整**。

---

## A. 源数据（EI 汇总表）相关

### A1. 颜色语义：红色 = 原表记载相对强度 >20%
- **依据**：源表 R64 合并单元格明确写"峰相对强度大于20%其峰信号标红色"。
- **实现**：红色 → `intensity_class = reported_gt20pct`；**不换算为任何数值**。
- **兜底**：若将来导入的表没有该声明，解析器自动降级为 `reported_present`（不猜）。

### A2. 空单元格 = `not_reported`，不是 `not_detected`
- **依据**：03 契约 A02；定性表没有扫描覆盖与检测阈记录，无法支撑"明确未检出"。
- **实现**：空单元格**不生成离子行**，因此永远不会变成排除某个候选的硬证据。

### A3. 名称中的 `(2NAc)` 表示 C2 为 N-取代，不占 O-甲基位
- **理由**：己糖胺的 C2 是 NHAc，不存在 O-甲基；若把 C2 同时算作 O-Me 与 NAc 会产生自相矛盾。
- **实现**：解析时 C2 从 O-甲基位剔除，连接位按 `U \ (M ∪ N位)` 计算。
- **验证**：修正后 7 条氨基糖记录的推导"连接方式"与源表标注**完全一致**，
  且全表 57 行**零冲突**——这是该假设成立的强证据。
- **若不成立**：改 `ingest/name_parser.py` 的 `_MOD_RE` 与 `chemistry/frameworks.py:available_after_n_substitution`。

### A4. 分组行标题用于推断骨架，糖名用于交叉校验
- **实现**：分组行（六碳糖 / 6-脱氧己糖 / 五碳糖）给骨架兜底，糖名（`_SUGAR_TO_SKELETON`）优先；两者不一致时产生警告，不静默采用其一。

### A5. 五碳糖记录按呋喃糖登记，但映射仍保留吡喃候选
- **依据**：源表注释"五碳糖只统计其呋喃糖 Araf、Xylf 的数据"；但 14.6.4 要求同一 PMAA 的多个来源必须全部保留。
- **实现**：`ring_form` 登记为 `f`；映射引擎对所有相容框架生成候选，因此 2,3-Me2-Ara 同时给出 `5-Araf` 与 `4-Arap`。

### A6. 全表还原试剂为 NaBD4
- **依据**：源表注释"此 PMAA 数据是使用 NaBD4 还原，而不是 NaBH4 还原"。
- **实现**：`reduction_label.anomeric_reduction = NaBD4`，`label_positions = [C1: D ×1]`。
- **注意**：若样品实际用 NaBH4，必须另建标签库；标签未知时系统自动把证据上限压到 `candidate`（LABEL_UNKNOWN）。

## B. 架构与技术选型

### B1. 用 SQLite 作为默认数据库（计划写的是 PostgreSQL）
- **理由**：当前是单机研究原型，SQLite 便于启动与回归。
- **边界**：SQLAlchemy 只隔离了大部分方言差异；当前依赖中没有 PostgreSQL 驱动，也没有
  Alembic 迁移、JSON/唯一约束、并发和备份恢复验证，因此不能宣称改 `PMAA_DB_URL` 即可生产迁移。
- **升级路径**：补驱动与迁移脚本，在真实 PostgreSQL 上跑同一验收集、并发幂等和恢复演练后再放行。

### B2. 前端不引入构建步骤（计划写的是 React/TypeScript）
- **理由**：研究用平台优先保证可运行、可审计、易部署；当前交互复杂度用原生 ES 模块足够，避免 Node 工具链成为部署门槛。
- **若不成立**：`/v1` 已是完整 REST 契约，前端可整体替换为 React 而不动后端。

### B3. 长任务同步执行（接口形态保持异步语义）
- **理由**：当前规模（每组分对数十条参考记录打分）在毫秒级。
- **若不成立**：接入计算队列时，`POST /v1/analyses` 返回 202 + `job_id`、`GET /v1/jobs/{id}` 查询状态即可，数据模型已预留 `status` 字段。

### B4. 原始 GC–MS 解析（M07）不在本版范围
- **依据**：计划 P4（第 10–12 周）任务；当前版本接受**已积分峰表**输入。
- **边界**：因此平台不评价色谱纯度与共洗脱；报告会显式写明这一局限（03 契约 A23）。

## C. 化学与判定规则

### C1. 定性离子检索打分 = 加权几何均值，查询侧召回权重 0.7
- **理由**：定性表只报告少量离子；若以"参考谱覆盖率"为主，离子数少的条目会靠小分母刷分，
  把"解释不了全部观测离子"的条目顶到前面（实测中出现过该问题）。
- **可调**：`config.SEARCH_DEFAULTS["qualitative_recall_weight"]`；阈值、离子比范围等需由独立标准验证集确定并版本化。

### C2. `near_tie_delta = 0.02` 作为并列判定阈值
- **理由**：计划 A13 要求 0.93 与 0.929 必须并列；0.02 是工程初值。
- **待定**：真实阈值应由近邻异构体盲测确定，写在 `config.py` 便于版本化。

### C3. 参考条目默认状态为 `reference_only`
- **理由**：来源为课程课件汇总表（E2 级），**未经本地标准实测**；未本地验证的条目不能支撑 `confirmed`。
- **影响**：当前库无法产出 `derivative_identity_level = confirmed`，这符合计划"不把候选伪装成确认"的要求。
- **升级路径**：经本地标准验证后，通过 `POST /v1/references/{id}/review` 置为 `locally_validated`。

### C4. 氨基糖分支条目进入 `quarantined`
- **理由**：14.4.2 —— 专项分支未完成实测验证前，不得签发自动确认结果。
- **实现**：保留为候选（可检索、可比对），但不参与确认，并在冲突列表中显式说明。

### C5. 保留窗口用"中心 ±3 SD"
- **理由**：计划 14.5.2 的初始建议；文献值只作候选提示。
- **前提**：需要同方法标准的重复观测分布；无分布时只给排序提示，不做确认也不做排除。

## E. 明确**没有**做的事

- 没有把 `+` 变成强度，没有对定性表跑全谱余弦。
- 没有因某个 m/z 未列出而排除候选。
- 没有从 PMAA 推断 α/β 或 D/L。
- 没有在无校准时输出 mol%。
- 没有把同一 PMAA 的多个原残基来源合并成一个"唯一解"。
- 没有把最高匹配分数当作正确概率展示。
- 没有让 LLM 输出直接写入正式结论字段。
- 没有在 QC 失败时签发正式报告。
- 没有用同一制备的分装冒充独立重复。
